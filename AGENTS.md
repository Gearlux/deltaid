# Deltaid Mandates

- **Adapter, Not Segmentor:** Deltaid is a thin Confluid-`@configurable` wrapper around `segmentation_models_pytorch` (smp). The base `marainer.trainer.LightningTrainer` step flow MUST remain unchanged — no overridden `training_step` / `validation_step`, no custom Lightning module behaviour. A thin subclass that only sets default `loss_fn` / `collate_fn` / `metrics` / `optimizer` in `__init__` (cf. `LightningSegmentationTrainer`) is permitted and is the canonical user-facing surface.
- **Per-Pixel Target Contract:** Targets are int64 per-pixel class-id masks; logits are `[B, C, H, W]`. `LightningSegmentationTrainer` constructs the loss internally as a plain `torch.nn.CrossEntropyLoss` with `ignore_index` exposed as a trainer param — there is no deltaid-owned loss adapter class. Any user-supplied override MUST be a class from `torch.nn`, `torchmetrics`, `segmentation_models_pytorch.losses`, `kornia.losses`, or another upstream library, passed verbatim under the trainer's `loss_fn` / `*_metrics` YAML keys. Don't introduce one-hot intermediates.
- **Generic Primitives Live in Waivefront:** Rasterization ops (`waivefront.targets.RegionsToSegmentationMaskOp`, target-only — it writes the `[H,W]` mask and leaves the input PIL; chain the generic `dataflux.ops.torch.ToTensorOp` to materialize the image tensor) and segmentation predictions sinks belong in `waivefront`, not `deltaid`. Deltaid stays focused on the model + collate + trainer/evaluator specialisation.
- **Collate Discipline:** `segmentation_collate_fn` MUST stack `[3, H, W]` images and `[H, W]` masks into batched tensors, preserving per-sample metadata for sinks.
- **Encoder Selection from YAML:** `DeepLabV3PlusModel.__init__` MUST forward `encoder_name`, `encoder_weights`, `num_classes`, and other smp constructor knobs verbatim. Don't shadow names; don't silently rewrite defaults.
- **Single-Pass Baseline First:** DeepLabV3+ is the first-class single-pass baseline. Multi-stage / cascade architectures (HRNet, UperNet, etc.) are additions, not replacements — keep the smp-backed surface minimal.
- **Discovery Tags (`task`/`role`):** Deltaid tags its classes `@configurable(task="segmentation", role=…)` — `DeepLabV3PlusModel` is `role="model"`, `LightningSegmentationTrainer` is `role="trainer"`, the evaluator `role="evaluator"` (each derives the matching `category`, e.g. `segmentation_model`, so navigaitor's `list_configurable_classes(category=…)` / `list_classes(task=…, role=…)` and the visual-editor form-spec offer them). Preserve the tags when adding/renaming — `tests/test_categories.py` pins them; a dropped tag silently empties the corresponding picker and drops the trainer out of navigaitor's `role="trainer"` scan (`TASK_REGISTRY` + `generate_task_config`). (The loss is a plain `torch.nn.CrossEntropyLoss` built in the trainer, so there is intentionally no `segmentation_loss`-tagged class.)
- **Deferred `num_classes`:** `LightningSegmentationTrainer` takes `num_classes: Optional[int] = None` and defers its metrics so an omitted count is derived from the dataset at run time (`marainer.dimensions`); an explicit value is honoured unchanged. Mirrors sonair's classification trainer — keep the trainer task-agnostic in shape (the base `marainer.trainer.LightningTrainer` flow is untouched).
